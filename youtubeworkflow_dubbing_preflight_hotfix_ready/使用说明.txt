Dubbing persistent-worker TorchCodec preflight hotfix
====================================================

问题
----
手动运行：
.venv_dubbing\Scripts\python.exe -u -m src.dubbing.torchcodec_probe --tools-bin tools\bin
可以正常完成，但控制面板在 Persistent .venv_dubbing worker 启动后，
由 worker 内部再次启动同一个 probe 时连续 60 秒超时。

这说明 TorchCodec / FFmpeg / PyTorch 本身可用；问题位于
“persistent worker -> 再启动 probe 子进程”的 Windows 运行上下文。

修复
----
1. 控制面板在启动 persistent worker 之前执行真实 TorchCodec/FFmpeg preflight。
2. preflight 通过后才启动 persistent worker。
3. 请求中携带 runtime_preflight_done=true。
4. persistent worker 收到该标记后不再重复启动嵌套 TorchCodec probe。
5. 直接 CLI / 非 persistent worker 路径仍保留原来的 preflight，不削弱安全检查。

安装
----
关闭控制面板。
把本 ZIP 解压到 youtubeworkflow 项目根目录并覆盖同名文件。

运行：
python verify_dubbing_preflight_hotfix.py

然后彻底重新启动控制面板，再尝试中文 AI 配音。

预期日志顺序
------------
[DUBBING] Runtime preflight passed before persistent worker startup.
[DUBBING] Persistent .venv_dubbing worker started.
然后进入 Demucs / VoxCPM2 等后续流程，而不再出现 TorchCodec probe 60 秒 x2 超时。
